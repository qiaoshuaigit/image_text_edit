# 图片文字修改工具（医学论文图改字）

> 自动识别图片中的文字，批量替换/移除，只改文字不动其他像素。
> 专为医学论文图片修改设计，支持超大分辨率医学大图。

---

## 一、项目背景

### 1.1 需求来源
用户是医学论文作者，经常需要修改论文中的图片文字（如把"Untreated"改成"Control"，把剂量数字从"10mg"改成"20mg"）。
传统方法用 Photoshop 手动擦除再打字，效率低且容易破坏图片质量。

### 1.2 核心痛点
- **只改文字，不动其他像素**：医学图对像素质量要求极高，不能模糊、不能变色
- **超大图片支持**：医学论文图经常是 10000×8000 像素以上、100M+ 大小的 TIFF/PNG
- **批量操作**：一张图上有几十处文字，需要批量替换
- **多平台部署**：Windows 本地、CentOS 7 云服务器都要能跑

### 1.3 技术选型历程
| 方案 | 为什么放弃 | 最终选择 |
|---|---|---|
| PaddleOCR | Windows 长路径限制导致安装失败 | RapidOCR（PaddleOCR 的 ONNX 版，轻量无依赖） |
| IOPaint（AI 擦除） | 模型太大、速度慢 | OpenCV Inpaint（Telea 算法） |
| Gradio share 外网访问 | 国内网络连不上 HuggingFace | 直接部署到云服务器 + 内网穿透 |

## 二、技术栈

| 模块 | 技术 | 版本要求 | 说明 |
|---|---|---|---|
| OCR 识别 | RapidOCR | rapidocr-onnxruntime >= 1.2.0 | PaddleOCR 模型的 ONNX 版，无需 PaddlePaddle |
| 文字擦除 | OpenCV Inpaint | opencv-python >= 4.5 | Telea 算法，用周围像素填充原文字 |
| 文字渲染 | PIL/Pillow | Pillow >= 9.0 | 加载系统字体，绘制新文字 |
| 界面框架 | Gradio | gradio >= 4.0 | Web 界面，表格操作，文件上传 |
| 图像处理 | NumPy + OpenCV | numpy >= 1.24 | 数组操作、颜色空间转换 |

## 四、功能特性

### 4.1 核心功能
- ✅ **自动 OCR 识别**：自动检测图片中所有文字区域和位置
- ✅ **批量操作**：替换 / 移除 / 不改，一键批量设置
- ✅ **查找替换**：按关键词批量匹配替换
- ✅ **每行独立设置字号**：表格里每行可以单独设置字体大小
- ✅ **统一字体/颜色**：全局字体选择、颜色自动/自定义
- ✅ **超大图片支持**：162M 医学大图、7.9 亿像素
- ✅ **导出高清 PNG**：原图尺寸、无损质量，不改动其他像素

### 4.2 表格列说明
| 列名 | 含义 | 可编辑 | 说明 |
|---|---|---|---|
| 识别文字 | OCR 识别出的原文 | ❌ 只读参考 | 显示用，不参与计算 |
| 原始框(px) | 文字框原始尺寸（宽×高） | ❌ 只读参考 | 仅供参考，修改无效 |
| 操作 | 对这行文字做什么 | ✅ 可编辑 | 填：不改 / 替换 / 移除 |
| 新文字 | 要替换成的新内容 | ✅ 可编辑 | 操作=替换时生效 |
| 字号(pt) | 新文字的字体大小 | ✅ 可编辑 | 0 = 自动适配，填数字 = 固定字号 |

## 六、关键设计决策

### 6.1 为什么用 RapidOCR 不用 PaddleOCR？
PaddlePaddle 在 Windows 上有长路径限制，安装经常失败。RapidOCR 是 PaddleOCR 模型的 ONNX 导出版，只需要 onnxruntime，轻量无依赖，安装成功率高。

### 6.2 为什么用 OpenCV Inpaint 不用 AI 擦除？
医学图要求像素级精确，AI 擦除（如 IOPaint）会生成"看起来像但不是真的"像素。OpenCV Inpaint 用周围真实像素填充，虽然简单但可靠，不会破坏图片质量。

### 6.3 为什么大图片用文件上传不用 Image 组件？
Gradio 自带的 Image 组件在处理超大数组时会崩溃。改用 gr.File 上传，后端用 PIL 读取原图，再缩放到显示尺寸预览，原图保留在内存里。

### 6.4 为什么字号单位用 pt 不用 px？
px 是图片像素尺寸，跟图片分辨率挂钩，用户不好理解。pt（点）是排版标准单位，用户更熟悉，也和 Word 里的字号对应。

## 七、已知限制

1. **不支持手动添加文字**：只能修改 OCR 识别出来的文字，不能在图片上新增文字
2. **字体依赖系统**：Windows 用微软雅黑/宋体/黑体，Linux 需手动安装字体
3. **颜色提取是平均色**：自动颜色模式是取原文字框内的平均色，不是精确的每个字的颜色
4. **Gradio 表格不支持单列只读**："原始框(px)"列虽然改了没用，但用户还是能编辑，只能靠说明文字提醒

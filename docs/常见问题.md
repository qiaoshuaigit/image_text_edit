# 常见问题与历史踩坑记录

> 本文档记录项目开发过程中遇到的所有问题和解决方案，避免重复踩坑。

---

## 一、安装相关问题

### 1.1 PaddlePaddle 在 Windows 上安装失败

**现象**：`pip install paddlepaddle` 报错，提示长路径问题。

**原因**：Windows 默认路径长度限制 260 字符，PaddlePaddle 的依赖路径太长。

**解决方案**：改用 RapidOCR（PaddleOCR 模型的 ONNX 版），只需要 onnxruntime，轻量无依赖。

---

### 1.2 CentOS 7 上没有 python38 包

**现象**：`yum install python38` 提示"没有可用软件包"。

**原因**：CentOS 7 官方源最高只到 Python 3.6，新版依赖（numpy>=1.24）需要 Python 3.8+。

**解决方案**：`install_centos.sh` 脚本里源码编译安装 Python 3.8，用 `python38` 命令调用。

---

### 1.3 Windows bat 脚本中文乱码

**现象**：在另一台 Windows 电脑上运行 install.bat，中文全部乱码。

**原因**：bat 文件编码和目标电脑的系统编码不匹配。

**解决方案**：所有 bat 脚本全部用纯英文，不写中文。

---

### 1.4 用户在压缩包里直接运行 install.bat 失败

**现象**：用户下载 zip 后，直接双击压缩包里的 install.bat，安装失败。

**原因**：压缩包里运行时，文件在临时目录，虚拟环境创建失败。

**解决方案**：install.bat 开头检测当前路径是否在 `Rar$` 或 `Temp` 目录，如果是就提示用户先解压。

---

## 二、功能相关问题

### 2.1 导出图片底色变了 / 颜色不对

**现象**：修改完导出 PNG，发现图片整体颜色变了。

**原因**：Gradio Image 组件用 RGB 顺序，OpenCV 用 BGR 顺序，颜色空间搞混了。

**解决方案**：所有颜色转换显式做，不能猜。
- Gradio → OpenCV：BGR = RGB[::-1]
- OpenCV → Gradio：RGB = BGR[::-1]

---

### 2.2 大图片上传后显示破碎占位符

**现象**：上传 162M 的医学大图，Gradio 显示破碎图标。

**原因**：Gradio 自带的 Image 组件无法处理超大数组。

**解决方案**：改用 `gr.File` 上传，后端用 PIL 读取原图，再缩放到显示尺寸预览。

---

### 2.3 PIL 报错"解压炸弹"

**现象**：读取 7.9 亿像素的大图，PIL 报错。

**原因**：PIL 默认有解压炸弹保护，超过 1.78 亿像素就报错。

**解决方案**：代码开头加 `Image.MAX_IMAGE_PIXELS = None` 关闭限制。

---

### 2.4 表格编号列可编辑导致索引错位

**现象**：用户在表格里手动改了编号列，生成结果时对应错了。

**原因**：用编号列做索引，但用户能编辑编号，导致错位。

**解决方案**：去掉编号列，用 DataFrame 的行号索引，用户改不了。

---

### 2.5 字号设置混乱（三个地方都能设字号）

**现象**：用户搞不清统一字号、固定字号、尺寸列到底以哪个为准。

**原因**：一开始设计了全局字号设置 + 滑块 + 表格列，太多地方能设，用户混淆。

**解决方案**：
- 去掉全局字号设置
- 表格里加"字号(pt)"列，每行独立设置
- 批量操作区域加"统一字号"输入框 + 应用按钮
- "原始框(px)"列明确标注是参考值，只读

---

## 三、性能问题

### 3.1 大图片生成结果很慢

**现象**：200M 的图片，点生成结果要等 20-30 秒。

**原因**：每一行文字都做一次完整的 BGR→RGB→PIL→BGR 全图转换，N 行文字 = N 次全图拷贝。

**解决方案**：
1. 批量渲染：一次性全图转 PIL，画完所有文字再一次性转回 BGR
2. ROI 局部擦除：只在文字区域做 Inpaint，不对整张图做

优化后：生成时间降到 5-8 秒。

---

## 四、外网访问问题

### 4.1 Gradio share 功能连不上

**现象**：`share=True` 启动后，生成的外网地址打不开。

**原因**：国内网络连不上 HuggingFace 的 CDN。

**解决方案**：放弃 Gradio share，直接部署到云服务器。

---

### 4.2 Cloudflare 隧道连不上

**现象**：用 cloudflared 做内网穿透，启动失败。

**原因**：国内网络连不上 GitHub 下载 cloudflared，也连不上 Cloudflare 边缘节点。

**解决方案**：推荐用 cpolar 国内内网穿透服务，或者直接部署到云服务器。

---

## 五、已知未解决问题

1. **"原始框(px)"列可以编辑**：Gradio Dataframe 不支持单列只读，虽然改了没用，但用户还是能点进去改，只能靠说明文字提醒。

2. **自动颜色是平均色**：auto 颜色模式是取原文字框内的平均色，不是精确的每个字的颜色。对渐变文字效果不好。

3. **不支持手动添加文字**：只能修改 OCR 识别出来的文字，不能在空白处新增文字。用户说暂时不需要，以后可能加。

4. **Linux 字体问题**：Linux 服务器上没有 Windows 字体，渲染出来的字体会不一样。需要手动安装中文字体。

---

## 六、部署相关注意事项

### Windows 部署包
- 全部脚本纯英文，不要写中文
- 不要用虚拟环境，直接全局安装（避免用户路径问题）
- 用清华镜像源加速 pip 安装
- 开头加压缩包临时目录检测
- 启动脚本开头加 Python 环境检查

### CentOS 7 部署
- yum 源没有 python38，必须源码编译
- 编译前先装依赖：`yum install gcc openssl-devel bzip2-devel libffi-devel`
- 编译完后用 `python38` 命令调用，不要覆盖系统 python3.6
